# 面试答案卡（结合瑞雪地膜 Agent 项目）

> 用法：每题**出声讲一遍**，读会 ≠ 会讲。标 `[考点]` 的是面试官真正在测的东西。
> 标 `[非本项目]` 的是别人项目的题——答通用理解 + 说明你的取舍即可，别硬编。
>
> **项目一句话**：面向地膜行业的中文 RAG Agent。单 Agent + ReAct + 工具编排；
> 知识库 1500+ 篇文献/国标，混合检索（向量+BM25+RRF+cross-encoder 重排），
> R@1 0.807；带引用 grounding；PG+Milvus 双存储；FastAPI 服务、多轮持久化。

## 一、项目宏观（1,2,3,4,10,24,30,35,43）

**1/10 为什么做 / 背景**
地膜行业选型、合规、田间问题分散在上千篇文献和国标里，人工查慢且不可溯源。纯大模型会幻觉、不知道私有标准。所以做一个**可溯源的领域知识 Agent**：把文献/国标做成可检索知识，Agent 按需查、带出处答，另配确定性计算工具（用量估算）。`[考点]`：有没有真实业务动机，而非"跟风做 agent"。

**2 市面上有哪些 agent**
通用超级体：Claude Code / Codex（编程）、deer-flow（LangGraph 超级 agent，我拿它当参考蓝图）、Manus、Coze/Dify（低代码）。框架层：LangGraph、AutoGen、CrewAI。`[考点]`：视野。**加一句判断**："它们是通用体所以功能爆炸，我是领域 agent，只取需要的子集。"

**3/30 讲下项目 / 演示细节**
按"业务→数据→检索→Agent→工程"顺序讲（别一上来堆名词）：① 业务问题；② 1500 篇 PDF 用 MinerU 解析成统一 IR，清洗去重切块入 PG，向量进 Milvus；③ 向量+BM25 混合、RRF 融合、cross-encoder 重排，R@1 从 0.587 提到 0.807；④ 包成工具交 ReAct Agent 编排，grounding 强制带引用；⑤ FastAPI 服务、多轮持久化、中间件（重试/降级/计时）。`[考点]`：能不能有主线、有数据、讲清取舍。

**4 开发框架**
LangChain `create_agent`（ReAct）+ LangGraph（图/状态/checkpointer）。对标 deer-flow 的 harness/app 分离——agent 核心不认识 HTTP，服务层才依赖它（ports-and-adapters）。`[考点]`：知道框架边界，而非"我用了 LangChain"一句话。

**24 AI 贡献代码占比 / 43,35 AI 辅助开发**
诚实答："AI 辅助写了相当比例，但架构、技术选型、每个决策的取舍是我做的、我能讲清"（指向 DECISIONS.md）。**关键**：面试官怕的不是"你用 AI"，是"你不懂自己的代码"。所以把 DECISIONS.md 当护身符——"为什么 MinerU 不用 GROBID""为什么 RRF 不加权分数"这种，AI 答不出，你能答。`[考点]`：AI 时代最核心的反问——你到底懂不懂你的项目。

## 二、大模型基础（5）+ 常见追问

**5 介绍 AI 大模型**
线上用 DeepSeek（v3/R1 系）——国内可用、性价比高、支持 function calling。会提 Qwen（本地部署过）、GPT/Claude（能力天花板）。`[考点]`：知道选型理由（成本/合规/能力）。

**追问 temperature / top_p**
temperature 控随机性（缩放 logits，越高越发散）；top_p 核采样（只在累积概率 p 的词里采）。RAG/工具场景我设**低 temperature（近 0）**求稳定可复现。`[考点]`：懂采样。

**追问 temperature=0 输出一定相同吗**
**不一定**。贪心解码是确定的，但：浮点非结合律 + GPU 并行归约顺序不定 + MoE 路由 + 批处理，都会引入微小差异。所以"近似确定"而非"绝对确定"。`[考点]`：这是区分背书 vs 真懂的题。

**追问 Transformer 原理**
核心是 self-attention：每个 token 用 Q·K 算与其他 token 的相关性、softmax 成权重、加权 V 聚合信息；多头并行捕捉不同关系；位置编码补顺序；FFN 做非线性变换；残差+LayerNorm 稳训练。`[考点]`：讲得清主干即可，别背公式。

## 三、RAG（6,14,20,36,39,42）+ [非本项目]（17,26）

**6 RAG 系统流程**
离线：文档→解析→清洗去重→切块→embedding→向量库。在线：query→检索→（重排）→拼上下文→LLM 生成。我的具体化：MinerU→IR→MinHash 去重→Small-to-Big 切块→PG+Milvus；检索是向量+BM25+RRF+rerank。`[考点]`：能把通用流程落到自己实现。

**14 检索优化策略（王牌题，往深讲）**
逐层递进，每层都有实测：① **混合检索**——纯向量对"PBAT""0.010"这种罕见词/标准号不稳，加 BM25 词法精确匹配，R@1 0.587→0.647；② **RRF 融合**——向量给余弦、BM25 给 ts_rank，量纲不同，用排名融合而非加分数；③ **cross-encoder 重排**——召回粗、重排精，R@1 0.647→0.807；④ **BM25 只用罕见词查**（DF<1%）——常见词淹没定位、还慢，只留罕见词召回+50%、快 60 倍；⑤ **Small-to-Big**——子块检索求准、返回父块求全。`[考点]`：这是你最强的题，把 DECISIONS #10-13 讲透，碾压。

**20/34 RAG 评估方案（高频）**
造评测集（query→标准答案 chunk）：合成（LLM 按 chunk 反向出题）+ 人工质检 + **TREC pooling**（多路检索结果并集人工标，缓解"只标了向量召回的"偏差）。指标：**Recall@k**（答案在前 k 的比例）、**MRR**（第一个正确答案的排名倒数均值）。逐层做消融证明每个组件的增益（自助置信区间验证显著性，不是手调挑最高）。`[考点]`：**"85% 召回率怎么算的"是必问陷阱**——答不出评测集怎么造 = 数字是编的。你有 150 题评测集 + 方法文档，这是硬通货。

**9→线上无标注怎么评估 / A/B**
线上没人工标签：① **A/B 测试**——新旧检索各分流量，比点击/满意度/人工采纳率；② 采样人工评；③ 隐式信号（用户是否追问、是否复制答案）。`[考点]`：区分离线指标 vs 线上评估。

**36/39 RAG 动态知识更新（企业知识库高频）**
① **增量入库**——内容寻址 ID（sha256），同文件同 ID，`ON CONFLICT DO UPDATE` 幂等 upsert，改了的重跑覆盖、没变的跳过；② **索引可重建**——文本在 PG（source of truth），Milvus 只是派生索引，随时重建；③ 定时/事件触发重新解析变更文档；④ **召回文档过期处理**——元数据带 version/date，检索可按时间过滤，或后台比对新旧、主动提示。`[考点]`：你的 PG+Milvus 分离 + 幂等 upsert 恰好答这题（DECISIONS #5,#7）。

**42 多阶段召回优化**
召回（向量+BM25 粗筛，要快要全）→ 融合（RRF）→ 精排（cross-encoder，慢但准，只对 30 个候选）。分阶段是因为"快"和"准"矛盾：前段负责别漏、后段负责排对。`[考点]`：理解"召回 vs 精排"分工。

**17 跨模块错误追踪知识库 / 26 基于代码构建知识库** `[非本项目]`
答通用："思路一样——把代码/日志/错误当文档做 RAG，按调用链/文件结构切块，元数据带模块/函数。我项目是地膜文献，没做代码知识库，但检索架构可复用。" `[考点]`：迁移能力 + 诚实。

## 四、Agent 架构与推理模式（11,13,16,18,22,31,38）

**11 LLM 幻觉原因及解决（必问）**
原因：模型按概率补全、不知道边界、私有/新知识没见过、长上下文注意力稀释。解决三层：① **RAG**——给它本地证据，别凭记忆；② **grounding**——强制"只依据材料答、没有就说没有、标引用、数字与原文一致"；③ **兜底**——检索为空直接答"资料中没有"、不调模型。我系统甚至会主动报告两段材料数值冲突而非瞎选。`[考点]`：你的 grounding（DECISIONS #14）是标准答案。

**16/13/38 推理模式 / 差异化 / 选择机制**
主流：**ReAct**（推理+行动交替，我用的，通用够用）、**Plan-and-Execute**（先规划再执行，适合步骤明确的复杂任务）、**Reflection**（自我批判重试，适合要高质量输出）、**CoT**（纯思维链，不带工具）。选择：任务简单/需灵活调工具→ReAct；步骤多且可预先规划→Plan；对输出质量要求高→加 Reflection。我选 ReAct：地膜问答是"按需查工具"，不需要预先规划。`[考点]`：能对比 + 说清自己为什么选 ReAct。

**31 其他 agent 范式**
除上面四种，还有 multi-agent（角色分工）、ReWOO（推理与观测解耦省 token）。`[考点]`：视野。

**18 多 Agent 执行策略选择/切换（你担心的题，这样答最强）**
"我做的是**单 Agent + 工具编排**。我评估过多 Agent——地膜决策子任务耦合、要共享检索上下文，多 Agent 的**协调开销、延迟叠加、上下文隔离成本**不划算。它的价值场景是**真正可并行的独立子任务**（如深度调研并行查多个子主题）、或每个角色要不同系统提示/工具。deer-flow 的 subagent 就是独立线程池+并发上限+**turn/token/loop 三轴熔断**。如果我要加，只会加一个'并行深度调研'子 agent，而不是无脑拆。" `[考点]`：**判断力 > 功能数量**。面经里堆了多 agent 的人照样挂——挂在讲不清取舍。你这个答案反而占优。

**22 复杂任务执行流程举例**
"用户问'10 亩地用 PBAT 膜要多少、有没有对应国标'：Agent 先调 `estimate_film_usage` 算用量，再调 `search_knowledge` 查国标，最后综合成带引用的答案。这就是 ReAct 多步工具编排。" `[考点]`：能举具体多步例子。

## 五、MCP / 协议 / Skills（7,12,15,23,27,29,37,41）

**7 MCP 和 Function Calling（超高频，问了 N 次）**
Function Calling 是**模型能力**——模型按工具 schema 输出"要调哪个工具+参数"。MCP（Model Context Protocol）是**标准协议**——把工具/数据做成独立服务，Agent 通过 MCP client 调，解耦工具实现和 Agent。关系：FC 是"模型怎么决定调"，MCP 是"工具怎么被暴露和连接"。我现在工具是进程内 `@tool`（本地 FC）；MCP 是把它升级成独立服务的方式。`[考点]`：分清"能力"和"协议"两个层次。

**12/23 MCP 核心 / 通信方式**
核心：标准化 tools/resources/prompts 的暴露，让任意 AI app 即插即用。通信：stdio（本地子进程）、SSE/HTTP（远程）。`[考点]`：知道传输层。

**15 特定推理模型不支持 MCP 的原因**
本质是**不支持 function calling / 工具调用**（有些纯推理模型只做文本生成，没训练工具调用格式），MCP 依赖 FC，所以用不了。`[考点]`：追到根因（是 FC 不支持，不是 MCP 本身）。

**37 MCP 和 skill 区别**
MCP 提供**外部工具/数据的连接**（跨进程、跨语言）；Skill 是**打包的领域指令/流程**（一段告诉 agent"怎么做某类任务"的知识+可用工具清单，deer-flow/Claude Code 的 skill）。MCP 给"能力"，skill 给"方法论"。`[考点]`：别混。

**27/41 A2A / A2A 与 MCP 区别**
A2A（Agent-to-Agent，Google）：**agent 之间**互相发现、通信、协作的协议。MCP：**agent 与工具/数据**之间。一句话：**MCP 是 agent↔工具，A2A 是 agent↔agent。** `[考点]`：一句话区分即可。

**29 Agent skills**
把高频任务打包成技能（触发词+流程+工具集+提示模板），agent 按需加载，避免系统提示塞满所有指令。`[考点]`：懂动态能力加载的意义。

## 六、Prompt 工程（8,25,40）

**8/25/40 写好 prompt / 实践 / 示例**
原则：① 角色+目标明确；② 结构化（分节：规则/上下文/输出格式）；③ 约束具体可验证（我 grounding prompt："只依据材料、没有就说没有、数字一字不改、标引用[1][2]"）；④ few-shot 给范例；⑤ 静态部分固定以命中 prefix cache 省钱。实践：迭代——先跑评测集看 badcase，再改 prompt，别拍脑袋。`[考点]`：有没有"可验证约束 + 迭代"的工程意识，而非"我写了句你是助手"。

## 七、工程 / 部署（9,21,28,32,33,34,19）

**9 多轮对话实现**
LangGraph checkpointer 按 thread_id 存会话状态到 **PostgreSQL**（重启不丢、多 worker 共享）。短期记忆=当前会话消息；长期记忆（跨会话偏好）我暂未做，会讲"可加向量化用户偏好、查询时召回"。`[考点]`：短期 vs 长期记忆分清；能讲存哪、怎么取。

**21 SSE 的局限性**
单向（只服务器→客户端，客户端要发消息得另开请求）、基于 HTTP 长连接、有代理/超时/重连问题、并发连接占资源。需要双向实时→用 WebSocket。我用 SSE 是因为 LLM 流式只需服务器单向推 token，够用且简单。`[考点]`：知道为什么用 SSE 而非 WS。

**28 长文本生成方案**
分段生成+拼接、大纲先行（先生成结构再逐节填充）、滑动窗口控上下文、Map-Reduce（分块处理再汇总）。`[考点]` `[部分非本项目]`：我项目是问答不是长文生成，答通用理解。

**32 模型预热**
服务启动时先加载模型/发一次 warmup 请求，避免首个真实请求慢（冷启动：模型加载、CUDA 上下文、JIT）。我的 embedding/rerank 模型懒加载单例，首次慢——生产上应 startup 预热。`[考点]`：懂冷启动。

**33 NL2SQL SQL 安全防护** `[非本项目]`
参数化查询、只读账号、SQL 白名单/AST 校验、禁 DDL/DML、LLM 生成后再校验+限制表/列范围、超时+行数上限。`[考点]`：通用安全意识。

**34 复杂任务准确率提升评估**
建任务级评测集（含中间步骤）、端到端成功率 + 分步正确率、消融对比、A/B。`[考点]`：同 RAG 评估思路。

**19 简历关键词提取** `[非本项目]`
答通用：NER/LLM 抽取+结构化，我项目不涉及。`[考点]`：诚实。
