# 架构说明

代码分两个包：ruixue_agent 是 agent 框架本身，不依赖 HTTP；ruixue_app 是 FastAPI 服务层，
依赖前者。以后要接飞书或 CLI，只用在 app 侧加适配，agent 逻辑不动。

## 目录

```
backend/
├── ruixue_agent/              agent 框架（不依赖 HTTP）
│   ├── agents/                装配：模型+工具+提示+checkpointer+中间件
│   ├── tools/                 16 个工具：用量、土壤/气候、天气、性能预测、
│   │                          配方筛选、知识检索、数据分析、联网搜索
│   ├── subagents.py           4 个专家子 agent（文献检索/配方优化/故障诊断/数据分析）
│   ├── memory/                跨会话记忆：运行后抽取事实，PG 存权威，向量召回，按用户隔离
│   ├── analysis/              上传数据：列名归一、校验、入库、和模型预测对比
│   ├── userkb/                用户自有知识库：上传 PDF/TXT/MD，问答自动引用
│   ├── predictors/            三个性能预测模型（降解率/透过率/拉伸强度）+ 环境取数
│   ├── mcp/                   MCP 客户端，连不上自动降级
│   ├── skills/                技能（SOP）按需注入
│   ├── eval/                  评测框架：轨迹抽取、判分、对照实验
│   ├── ingestion/             离线入库：MinerU 解析、清洗去重、分块、双写
│   ├── persistence/           SQLAlchemy 模型 + Alembic 迁移
│   ├── rag/                   在线检索：向量+BM25、RRF 融合、重排、带引用生成
│   └── models.py checkpointer.py config.py guardrails/
├── ruixue_app/                FastAPI 服务层
│   ├── main.py                /chat(SSE)、/datasets、/kb/docs、/metrics、报告导出、健康探针
│   ├── runs.py                异步运行：后台线程池 + Redis Stream，断线可恢复
│   ├── auth.py quota.py       JWT / API Key，每日配额
│   ├── mcp_server.py          MCP 服务端（默认关闭）
│   └── metrics.py report.py observability.py security/
├── tests/ scripts/ data/ config/
frontend/                      Next.js 聊天界面
docker/                        compose 编排 + nginx
scripts/ops/                   部署、备份、告警巡检
```

## 一次请求的路径

```
用户提问
  nginx（唯一入口）
  鉴权 -> 限流 -> 配额
  建 Run 记录，agent 转后台线程池跑
  中间件链（注入防护、上下文压缩、重试、计时、错误兜底）
  ReAct 循环：模型决定调哪个工具，看结果再决定下一步
  工具层：检索 / 预测 / 环境 / 联网 / 派专家
答案带出处流式返回，运行记录落库，记忆异步抽取
```

## 设计上的几个决定

详细取舍见 [DECISIONS.md](../DECISIONS.md)，这里列最重要的：

- 文本只存 PostgreSQL，Milvus 只放向量。PG 丢了要重跑 5 小时解析，Milvus 丢了几分钟重建，
  备份只备 PG。
- 检索用子块（短，容易命中），命中后返回父块（长，上下文全）给大模型。
- 检索到的材料强制带出处和年份，答案里的数字要和原文一致，检不到就说没有。
- agent 不绑 HTTP 请求，跑在后台线程池，用户断开连接后任务继续执行并写入数据库。
- 中间件顺序是刻意的：注入防护在最外层（上下文压缩会把用户原文喂给摘要模型），
  错误兜底在最内层，计时包在错误处理外面（失败调用也要有耗时记录）。
