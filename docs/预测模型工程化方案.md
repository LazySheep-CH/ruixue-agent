> 可测试、可运维的能力。本方案先评审、后动手;第一步只落地 DR,跑通端到端再扩展。

## 1. 分层与目录(训练/服务分离 —— MLOps 铁律)

```
ruixue_agent/predictors/         # 预测子系统(与 rag/ persistence/ 平级,不认识 HTTP)
├── schema.py                    # 每个模型:特征顺序 / 单位 / 合理范围 / 默认值(领域常识)
├── registry.py                  # 加载"模型+模型卡";懒加载单例;加载时【校验schema+版本】
└── predict.py                   # 预测封装:填默认→按序组装DataFrame→预测→带置信/免责

ruixue_agent/tools/predictor.py  # predict_degradation 等工具(薄封装,调 predictors)

scripts/train/                   # 离线训练(不进服务运行时)
├── _common.py                   # 交叉验证、指标、数据哈希、模型卡写出(复用)
└── train_dr.py                  # 训练 DR:读数据→CV评估→拟合→存模型+模型卡

RuiXue-Model-Store/predictors/   # 模型二进制(【git 忽略】,路径走 config)
└── DR/
    ├── DR_model.joblib
    └── DR_model_card.json
```

**为什么这么分**:训练是"一次性、慢、要数据"的离线动作;服务是"高频、快、只加载"的在线动作。
两者混在一起 = 起服务时莫名其妙要读训练数据、装训练依赖。分开是企业标准。

## 2. 数据规范(血缘 + 固定)

- 训练入口数据锁定为 `DR.csv`(记录来源路径);训练时计算并写入其 **sha256**。
- 特征列表【显式写死】在 `schema.py`,不靠"除了 target 都是特征"这种隐式约定。
- 目标列、单位、合理范围一并声明(范围用于服务端输入校验:超范围给告警)。

## 2.1 变量字典(数据契约)+ 审计发现

**三份数据同名变量已审计,发现三类问题,必须在字典里显式处理:**

| 类型 | 发现 | 处理 |
| --- | --- | --- |
| 命名漂移 | 湿度:WVTR `Humidity` / TS `Air_Humidity_pct` | 统一标准名 `relative_humidity_pct` |
| 语义漂移 | `Temperature_C`:DR 环境温(−2~58)vs TS 含测试温(≤185);`Precipitation_mm`:DR 累计(≤15500)vs 单月 | 字典中**分开定义**,服务层**按模型分别映射**,禁止一个输入喂三家 |
| 数据质量 | `Soil_pH` 达 13.7(>11 不可能);`Thickness_um` 达 75200(=7.5cm 不可能) | 训练前校验/剔除异常行(见 §3.1) |

**变量字典**:每个"标准变量"声明 `标准名 / 单位 / 类型 / 合理范围 / 默认值`,并为每个模型给出
`标准名 → 原列名` 映射。对外只有一套规范词汇,对内各模型保留其训练时的原始列(不改模型)。
标准名沿用 snake_case + 单位后缀(如 `mean_temperature_c`、`cumulative_precipitation_mm`、
`relative_humidity_pct`、`soil_total_n_mg_kg`、`soil_organic_carbon_g_kg`)。

## 3. 训练规范(可复现)

- `random_state` 全程固定(拆分、模型)。
- 依赖锁定:pandas、scikit-learn 写入 `pyproject.toml`(uv.lock 固定版本)。
- 评估:**K 折交叉验证**报 R² / RMSE / MAE(不只一个 train/test 数字)。
- 训练完在**全量数据**上拟合最终模型(服务用),CV 指标仅作评估记录。
- 算法:见 §7 待定(ExtraTrees 或 XGBoost)。

## 3.1 数据质量校验与清洗(训练前,企业级必做)

**行删除策略(用户定,硬规则):**
- **DR、WVTR:不删行** —— 越界值 **winsorize(裁剪到合理范围)**,整行保留。
- **TS:允许删行**(删物理不可能的行)。
- **所有数据集:绝不删变量(列)** —— 高缺失列一律**插补**保留,不丢列。

**清洗策略(分层,写成可复现管道步骤,自动出数据质量报告):**

| 情况 | DR/WVTR | TS |
| --- | --- | --- |
| 物理不可能(pH>11、比例>100、降解率>100 等) | **裁剪到边界**(不删行) | **删除该行** |
| 可疑但可能合理(厚度>2mm、温度>60℃) | 先诊断:散点→保留/封顶;成簇→查单位 | 同左,谨慎删 |
| 缺失 NA(高缺失列) | **MissForest 插补**(见 §3.2),加"是否缺失"标志位 | 同左 |
| PLA+PBAT≠100 | **保留**(多组分配方,合理) | 保留 |
| Fertilizer 编码不一致 | 统一 `0=未使用,1=使用`(TS 1→0/2→1;WVTR 1→1);各模型用各自编码独立训练 | 同左 |

- 校验按 §2.1 变量字典范围执行;`data.quality` 记录:裁剪/删除行数、超界变量、插补比例。
- 已知(TS):66 行 pH>11、317 行厚度>2mm、54 行温度>60;类别列 Recyclable/UV 实为连续量。

## 3.2 缺失值插补:用 MissForest(实测优于论文的 KNN)

论文用 `KNNImputer(k=5)` 在整表上填 —— 实测在高缺失列上**方差塌缩**(填出一片雷同值)。
我们改用 **MissForest(IterativeImputer + ExtraTrees 迭代插补)**,遮值实验对比(WVTR,遮 Temperature):

| 方法 | RMSE(越低越准) | 填充值 std(真值 8.65) |
| --- | --- | --- |
| KNN(论文) | 5.50 | 6.57(塌缩) |
| MICE(线性) | 7.25 | 5.70(塌缩最重) |
| **MissForest(树)** | **4.55** | **8.85(不塌缩)** |

- 插补器放进 **Pipeline,只在训练折上 fit**(无数据泄露),随模型保存 → 服务端一致插补。
- 高缺失列加**缺失标志位**;每列插补比例记入模型卡。DR 零缺失,无需插补。

## 4. 模型卡(Model Card)—— 每个模型必带

`DR_model_card.json` 字段:
```json
{
  "schema_version": 1,
  "name": "DR",
  "target": "target_degradation_pct",
  "algorithm": "ExtraTreesRegressor",
  "algo_params": { "...": "..." },
  "feature_order": ["pla_pct", "pbat_pct", "..."],
  "metrics": { "cv_r2": 0.0, "cv_rmse": 0.0, "cv_mae": 0.0, "cv_folds": 5 },
  "data": { "file": "DR.csv", "sha256": "...", "n_rows": 699 },
  "env": { "python": "3.13", "scikit_learn": "1.9.0", "joblib": "1.5.3" },
  "created_at": "<训练时间,由训练脚本注入>",
  "notes": "..."
}
```
**作用**:溯源(哪份数据、什么环境训的)+ 服务端据此校验(schema/版本对不对)。

## 5. 服务端规范(加载即校验,fail fast)

- `registry.load(name)`:懒加载单例(像 checkpointer);加载后立即校验:
  - 模型的 `n_features_in_` == `len(model_card.feature_order)`(schema 一致);
  - `model_card.env.scikit_learn` == 当前 sklearn 版本 → 不一致按策略【告警或拒绝】
    (这是根治版本债的地方)。
- `predict.py`:
  - 入参是**用户友好**的(配方 + 少数已知);未知的环境/土壤特征用 `schema.py` 的**领域默认值**填;
  - 用 `feature_order` 组装成**带列名的 pandas DataFrame**(避免"no feature names"告警,保证列序正确);
  - 返回预测值 + **免责说明**(哪些特征用了默认值 → 结果仅供参考)。
- 输入校验:配方比例 0–100、厚度>0 等,用 Pydantic 或显式检查;超合理范围给告警。

## 6. 测试规范

- **schema 一致性**:模型期望特征数 == 模型卡 feature_order 长度。
- **加载+预测冒烟**:对一条已知输入预测,结果落在合理区间(如降解率 0–100%)。
- **默认值填充**:只给配方时能预测、且明确标注了哪些走了默认。
- **版本守卫**:模型卡记录的 sklearn 版本与运行版本不一致时,行为符合预期(告警/拒绝)。

## 7. 待定:算法口径(需你拍板)

| 选项 | 依赖 | 保真度 | 适用 |
| --- | --- | --- | --- |
| **ExtraTrees**(推荐) | 仅 scikit-learn | CV R²≈0.95,对齐你原 agent_ready 模型 | 服务最轻、依赖最少 |
| **XGBoost** | 需加 `xgboost` | 对齐论文基线 R²≈0.978 | 要与发表结果一致时 |

推荐 ExtraTrees:纯 sklearn、服务端最轻,且与你之前"agent-ready"选的族一致。

## 11. 最终结果(全 TabPFN 填充)

| 模型 | 最优算法 | CV R² | 填充 | 备注 |
| --- | --- | --- | --- | --- |
| DR | XGBoost | 0.9496 | 无需(零缺失) | 对齐 JHM 论文,数据干净 |
| WVTR | ExtraTrees | 0.8493 | TabPFN | 诚实口径;KNN 口径 0.88(含塌缩虚高) |
| TS | ExtraTrees | 0.8671 | TabPFN | 超过原 paper_comparable 0.863 |

**TabPFN 是实测最强填充器**(遮值实验 RMSE 比 MissForest 低 27%、比 KNN 低 40%,且不塌缩)。
用它填充后:TS R² 反升(0.847→0.867;分类列已修正为整数,去掉小数码伪信号),WVTR 微降(0.88→0.857)——因为 TabPFN 戳破了
KNN 目标填充的"塌缩虚高"。

**SHAP 因子排名 vs 论文**(用论文同款 XGBoost 算):
- DR:温度/时间/降水/PLA —— 对上 JHM 论文 top(4/5)。
- WVTR:降水/厚度/面积对上论文物理项;但 **UV(论文 #2)在 TabPFN 填充下掉出前列**——
  UV 缺失 85%,其重要性是 KNN 插补伪影(重缺失列的 SHAP 不可靠)。
- TS:PBAT/厚度主导(力学正确);Fertilizer(缺 95%)冒高亦为插补伪影。

**关键科学结论**:稳的因子(降水/厚度/温度/配方)对齐论文与自然科学;脆的因子(UV/Fertilizer)
是重缺失列的插补伪影 —— 用最强填充器审出了论文可能不稳的结论。

### 12.2 变量映射(NASA POWER → 模型特征),单位天然对齐

| 模型特征 | NASA 参数 | 换算 |
| --- | --- | --- |
| `solar_rad_MJm2d` | `ALLSKY_SFC_SW_DWN` | 直接用(同为 MJ/m²/day) |
| `Temperature_C` | `T2M` | 直接用(°C) |
| `Precipitation_mm` | `PRECTOTCORR` | 累计 = 日均 × 天数(DR);单期直接用 |
| `Humidity` / `Air_Humidity_pct` | `RH2M` | 直接用(%) |
| `soil_moisture_pct` | `GWETTOP` | × 100 |
| **`UV`** | `ALLSKY_SFC_UVA` | **见 §12.3 标定式** |

### 12.3 UV 单位破解(关键发现)

原始数据 UV 列表头不可信。用刘子文验证数据(已知经纬度与起止日期)反推:

```
UV_累计 = 6140 × ALLSKY_SFC_UVA(MJ/m²/day) × Time_days
```

标定证据:江苏南京(119.82, 33.99)比值 **6142.4**;新疆尉犁(86.26, 41.36)比值 **6137.6** ——
两地相隔约 2000 km、气候带迥异,比值差 **0.08%**,证明这是单位换算常数而非巧合。
另佐证:训练数据中 `UV/Time_days` 稳定聚类(WVTR 中位 4584、TS 4543),
且 UV 与 Time_days 相关 0.89–0.91,证实 UV 是累计量。常数已写入 `schema.UV_PER_UVA_MJ`。

### 12.4 顺带修正的数据 bug

- **Fertilizer 编码反了**:课题组约定 `1=使用、2=未使用`(依据验证数据表头
  "Fertilizer（1使用/2未使用）");原先 TS 编成 `1→未使用` 是错的,已改为 `{1:1, 2:0}`。
- **验证表列错位**:该表 `UV` 列实为累计降水、`Precipitation` 列实为 UV(按数值量级判定)。

### 12.5 仍无解的缺口

`micro_shannon` / `micro_chao1`(土壤微生物多样性):**无全国尺度可公开获取数据集**
(现有研究均为区域采样)。只能用训练中位数兜底并明确标注"估计值"。
