# RAG 评测与优化标准作业程序(SOP)

本文件规定评测集怎么建、指标怎么算、优化怎么做。**一旦冻结,中途不改流程**——
这是为了堵住两类常见错误:评测集太小(测出噪声当结论)、边试边换(没先规划消融矩阵)。

## Phase 1 — 评测集构建 → 冻结

### 1.1 规模(统计功效决定,非拍脑袋)

配对比较两个检索系统用 **McNemar 检验**(同一批 query 跑两套系统,看结果不一致的对子)。
要在 α=0.05、power=0.8 下稳定检测 **5 个百分点** 的 recall 差异,需 **n≈300–400**。

| 规模 | 能可靠分辨的最小差异 | 判断 |
| --- | --- | --- |
| 26(单层) | ~20pt | 太粗,小改进全是噪声(上一轮翻车的根因) |
| **320(总)/每层 80** | **~5pt** | ✅ 采用 |

### 1.2 分层配额(策略固定,来源随语料储量)

| 策略 | 配额 | 出法 |
| --- | --- | --- |
| fact(专业措辞) | 128 | 读单块,问其中精确指标 |
| user(口语) | 96 | 读单块,用一线大白话重问同一知识点 |
| multihop(跨块) | 48 | 读同文档两块,问需综合才能答的题 |
| noans(拒答) | 48 | 凭领域常识出库内必然没有的题 |

**来源受语料储量约束**:标准规范仅 157 块/37 文档,现实上限约 55 道(每文档≤3题);
期刊论文 13496 块,承担其余。最终来源比例约 标准规范 20% / 期刊 80%。

### 1.3 出题与标注

- **出题**:Claude 逐块阅读真实语料后手工撰写(不用 LLM 批量生成,避免词汇泄漏)。
- **标注**:单 gold —— 出题绑定的依据块即金标准(fact/user 各 1,multihop 2)。
- **工具**:`scripts/eval_author.py`(去重 + 段号泄漏检测 + 拉真实块摘要)。

### 1.4 质量门

- 程序:去重(问题文本)、段号泄漏检测(`_LEAK` 正则)。
- 人工:专家审核 `review_answerable.csv` / `review_noanswer.csv`,记 Cohen's Kappa 或通过率。

### 1.5 冻结

达标后固化为 `evalset.jsonl`,冻结,之后**只读**。优化阶段不得改评测集
(否则等于在考卷上改答案)。

## Phase 2 — 评测协议

- **检索层**:Recall@k、MRR、nDCG@k(`rag/metrics.py`)。
- **生成层**:接 agent 时引入 **RAGAS**(faithfulness / answer_relevancy / context_precision)。
  当前阶段暂不做——无生成场景落地。
- **拒答**:noans 在生成层评(检索永远返回结果,拒答是生成层职责)。
- **报告**:分层 + 总体 + bootstrap 置信区间。

## Phase 3 — 优化(消融矩阵,一次列全)

先把所有维度列死,一轮系统跑,**不再边想边加**:

| 维度 | 候选 |
| --- | --- |
| embedding | bge-small(现役)/ bge-m3 / bge-large |
| 混合权重(向量:BM25) | 1:0 / 1:0.3 / 1:0.5 |
| fanout | 3 / 5 / 8 |
| rerank | 开 / 关 |
| chunk 大小 | 现行 / 更大父块 |
| query 改写(带闸门) | 关 / 开 |

每维度 A/B,控制变量。**显著性**:McNemar / bootstrap CI。
**合入标准**:置信区间不含 0 且多 seed 稳健。其余记录归档,不上线。
