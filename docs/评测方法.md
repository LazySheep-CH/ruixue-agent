# 检索评测方法

没有评测集,所有优化都是"感觉变好了"。 这份文档说明评测集怎么造、指标怎么算、
每层增益怎么量出来的。相关脚本:`scripts/eval_author.py`(出题/定稿工具)·
`pool_evalset.py`(多标注)· `run_eval.py`。评测集已冻结为 `data/eval/evalset.jsonl`(338 题)。

## 指标:Recall@k 与 MRR

| 指标 | 回答什么 | 为什么需要它 |
| --- | --- | --- |
| Recall@k | 标准答案在前 k 个里吗 | 检索是 RAG 的天花板。没检索到 → 大模型手里没材料 → 重排/prompt/换模型都救不回来 |
| MRR | 第一个标准答案排第几(倒数) | Recall@5 里排第 1 和排第 5 得分相同,但对大模型完全不同,排第 5 意味着前面 4 段无关材料在带偏它 |

Recall 看"找没找到",MRR 看"找得好不好",两个一起看才完整。实现见 `rag/metrics.py`,
标准答案是集合(一题可有多个正确块)。

## 评测集怎么造

系统未上线、没有真实用户日志。评测集由具备领域理解的作者逐块阅读真实语料后亲手撰写,
而非让大模型批量生成。原因:大模型看着原文出题会把措辞偏向原文,检索因词汇重叠而虚高;
人工出题能刻意制造词汇鸿沟(尤其口语题),量到的才是真实检索难度。

### 四种出题策略

每题"依据哪个块"记录在数据字段里(`primary_gold` / `gold_text` / `title` / `source`),
追溯靠数据本身,不靠出题脚本(出题脚本一次性,题产出后已删)。338 题实际分布:

| 策略 | 数量 | 怎么出 | 考什么 |
| --- | --- | --- | --- |
| fact | 142 | 读单块,用专业措辞问其中的精确指标 | 精确事实检索(数字、型号、规范条款) |
| user | 100 | 读单块,用一线口语重新问同一知识点 | 词汇鸿沟下的语义检索(最难) |
| multihop | 48 | 读同一文档的两个块,问需综合两块才能答的题 | 跨块组合 |
| noans | 48 | 凭领域常识出库里必然没有的题(实时报价/未公开配方/超范围) | 拒答能力(生成层评) |

来源:标准规范 38 + 期刊论文 252(标准规范总库仅 157 块,13% 是语料上限);112 个依据文档。

每题的标准答案 = 出题时逐块核过的依据块。 我读了那个块、确认答案在其中才出的题,
所以 (问题 → 那个块) 是经人工确认的标准答案,fact/user 各 1 个,multihop 2 个。

### 为什么用严格单标注,不做 reranker 自动扩标

出题只绑定一个标准答案,但库里另一段同样能答的段落可能存在,检索返回它却被判 0 分,
会低估 recall。TREC 的解法是 pooling:多路检索建候选池,逐条判"能不能答",能答的全算
标准答案。

我们试过用本地 cross-encoder(rerank 模型)当这个"判官"自动扩标,实测否决:

- 对一道"吐丝期后普通黑膜膜下温度高几度"的题,依据块得分 0.999(确实有答案),但另有
  近 10 个"地膜温度"话题块也拿到 0.92~0.98,它们只是同话题,答不出那个具体数字。
- cross-encoder 的分数刻画的是相关性,不是可答性,两者在 0.9+ 区间切不开。
  照阈值自动扩标会平均给每题标 9 个"标准答案",把 recall 反向刷虚高。

结论:采用严格单标注(与 MS MARCO / Natural Questions 的单相关段落基准一致),保守、可复现。它的代价是"检索找到另一段有效答案时被算作未命中",这部分低估由
后续 TREC 式专家 pooling(人工判官,而非 LLM 判官)修正,不用不可靠的自动判官凑数。

## 当前基线与优化过程

逐步优化(基线 → 查询改写 → 多标注 → fanout)的完整数据与决策见
[检索优化记录.md](检索优化记录.md)。当前上线管线(向量 + BM25 + rerank,fanout=2,
默认不含查询改写,多标注下改写无净收益且评测对它不公平,见优化记录)的真实基线:
R@3 0.910 / Recall@5 0.952 / Recall@10 0.979 / MRR 0.849,分策略 R@3
fact 0.965 / multihop 0.896 / user 0.840。检索层达标(Recall@5/10、MRR 超企业上线线)。

- nDCG 不测:下游是大模型读 top-k,不在乎相关块内部精确排序,核心是 Recall/MRR(见优化记录)。
- noans 题不计入 Recall/MRR,检索器永远返回结果,"拒答"是生成层的职责,须在答案层评。

## 复现

评测集是最终产物(`data/eval/evalset.jsonl`,338 题),无需重跑出题。

```bash
uv run python scripts/run_eval.py            # 上线管线(向量+BM25+rerank)
uv run python scripts/run_eval.py --rewrite  # 叠加查询改写
uv run python scripts/run_eval.py --ab       # 逐层对比:纯向量 / +BM25 / +rerank
```

如需扩题,用 `scripts/eval_author.py` 的 `append_batch` / `append_noans`(去重+段号泄漏检测+拉块摘要)。
